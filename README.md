# 🤖 AI Meeting Assistant

AI system that analyzes meeting transcripts and automatically generates:
- **Meeting summaries**
- **Action items**
- **Responsible persons**
- **Deadlines**
- **Answers to questions about the meeting**

The project evaluates **Large Language Models (LLMs)** and implements a **RAG-based meeting assistant** that retrieves relevant meeting context before generating responses. It supports both typed transcripts and real meeting audio files processed through a WhisperX transcription pipeline. The system supports **Arabic and English meetings** with automatic language detection.

---

# 📌 Project Components

### 📂 data
Contains meeting transcript datasets used for testing the models and the RAG system.
- `meeting_transcripts.json` — original dataset
- `meeting_transcripts_mixed.json` — Arabic/English mixed dataset
- `meeting_transcripts_mixed_rag.json` — dataset used for RAG pipeline
- `meeting_transcripts_audio.json` — dataset generated from real audio transcripts *(new)*

### 📂 prompts
Prompt templates used for:
- Meeting summarization
- Task extraction
- Mixed-language transcript understanding

### 📂 llm_testing
Python scripts used to test different **LLM models**.
```
llm_test_llama.py
llm_test_mixtral.py
```

### 📂 llm_results
Contains outputs generated from the tested LLM models.

### 📂 RAG
Core modules implementing the **Retrieval-Augmented Generation pipeline**.
- **chunking.py** → splits meeting transcripts into smaller chunks
- **embeddings.py** → generates vector embeddings using `all-MiniLM-L6-v2`
- **vector_store.py** → stores embeddings in ChromaDB with cosine similarity
- **rag_pipeline.py** → retrieves relevant context and generates answers using Groq LLM

### 📂 TTS
Text-to-Speech module using **edge-tts** (Microsoft Neural Voices).
- **coqui_tts.py** → converts LLM answers to speech with automatic language detection
  - Arabic meetings → `ar-EG-ShakirNeural`
  - English meetings → `en-US-JennyNeural`
- Audio results saved to `RAG/audio_results/`

### 📂 audio_pipeline
Modules for processing real meeting audio files and converting them into transcripts.
- **audio_preprocessing.py** → converts audio to WAV, mono, 16kHz, and removes silence
- **audio_transcription.py** → transcribes audio using WhisperX with speaker diarization
- **creating_dataset_from_audio.py** → converts WhisperX transcripts into RAG-ready JSON dataset

### 📂 audio_clean
Contains preprocessed audio files ready for transcription.

### 📂 transcripts
Contains transcribed meeting text files generated by WhisperX.
Each file includes speaker labels and timestamps.
```
[0.11-1.09] SPEAKER_01: Good morning, everyone.
[11.06-11.62] SPEAKER_00: Good morning.
```

# ⚙️ System Workflow

### Full Pipeline (Audio → RAG → TTS)
```
Meeting Audio Files
        ↓
Audio Preprocessing
(mono, 16kHz, noise removal)
        ↓
WhisperX Transcription
(speech-to-text + speaker diarization)
        ↓
creating_dataset_from_audio.py
(speaker mapping + JSON dataset)
        ↓
Chunking
(3 utterances per chunk)
        ↓
Embeddings
(384-dim vectors, all-MiniLM-L6-v2)
        ↓
Vector Database (ChromaDB)
(cosine similarity index)
        ↓
Similarity Search
(top-k relevant chunks)
        ↓
LLM (Groq — llama-3.1-8b-instant)
        ↓
Generated Answer
        ↓
edge-tts (Text-to-Speech)
(Arabic or English voice auto-detected)
        ↓
Audio Output (.mp3)
```

# 🚀 Features
- **Meeting summarization**
- **Task extraction** *(structured JSON: task, assignee, due_date)*
- **Question answering about meetings**
- **Automatic Arabic/English language detection** for both answers and TTS
- **RAG-based semantic search** over meeting content
- **Audio-to-transcript pipeline** using WhisperX
- **Speaker diarization** (identifying who said what)
- **Audio-to-RAG integration** — real audio feeds directly into the RAG pipeline
- **Text-to-Speech output** using Microsoft edge-tts (no GPU required, internet required)
- Results saved automatically as JSON for evaluation

# ▶️ Running the Project

## Option A — RAG Pipeline with typed transcripts

### 1️⃣ Activate the virtual environment
```bash
venv\Scripts\activate
```

### 2️⃣ Install dependencies
```bash
pip install -r requirements.txt
```

### 3️⃣ Add your API key
Create a `.env` file in the project root:
```env
GROQ_API_KEY=your_api_key_here
```

### 4️⃣ Set up TTS virtual environment
```bash
python -m venv venv_tts
venv_tts\Scripts\python.exe -m pip install -r requirements_tts.txt
venv_tts\Scripts\python.exe -m pip install edge-tts
```

### 5️⃣ Fix encoding for Arabic transcripts (run once when adding new files)
```bash
pip install chardet
python fix_encoding.py
```

### 6️⃣ Run the pipeline
```bash
python main.py
```

### 7️⃣ Choose a task when prompted
```
1 - Generate Meeting Summary
2 - Extract Tasks
3 - Ask a Question
4 - Exit
```

> **Note:** If you add new meeting transcripts, delete the `RAG/chroma_db` folder and re-run `main.py` to rebuild the index.

---

## Option B — Full Pipeline (Audio → RAG)

> ⚠️ WhisperX requires Python 3.10. Use a separate virtual environment for steps 1–3.

### 1️⃣ Create and activate a Python 3.10 virtual environment
```bash
py -3.10 -m venv venv310
venv310\Scripts\activate
```

### 2️⃣ Install audio pipeline dependencies
```bash
pip install -r requirements.txt
```

### 3️⃣ Set your HuggingFace token
```bash
# Windows:
setx HF_TOKEN "your_token_here"

# Mac / Linux:
export HF_TOKEN="your_token_here"
```

### 4️⃣ Preprocess audio files
```bash
python audio_pipeline/audio_preprocessing.py
```
Reads from `audio/`, saves cleaned files to `audio_clean/`.

### 5️⃣ Transcribe with WhisperX
```bash
python audio_pipeline/audio_transcription.py
```
Saves transcripts to `transcripts/` with speaker labels and timestamps.

### 6️⃣ Switch back to the main virtual environment
```bash
venv\Scripts\activate
```

### 7️⃣ Run the integration script
```bash
python audio_pipeline/creating_dataset_from_audio.py
```
Reads all `.txt` files from `transcripts/`, maps speaker labels to real names, and saves `data/meeting_transcripts_audio.json`.

### 8️⃣ Fix encoding if transcripts contain Arabic
```bash
python fix_encoding.py
```

### 9️⃣ Run the RAG pipeline
```bash
python main.py
```

# 🌍 Arabic & English Support

The system automatically detects the language of each meeting and:
- Responds in the **same language** as the meeting context
- Uses the appropriate **TTS voice**:
  - Arabic → `ar-EG-ShakirNeural`
  - English → `en-US-JennyNeural`

When adding Arabic transcript files, run `fix_encoding.py` once to ensure all files are saved as UTF-8.
