# 🤖 AI Meeting Assistant

AI system that analyzes meeting transcripts and automatically generates:
- **Meeting summaries**
- **Action items**
- **Responsible persons**
- **Deadlines**
- **Answers to questions about the meeting**

The project evaluates **Large Language Models (LLMs)** and implements a **RAG-based meeting assistant** that retrieves relevant meeting context before generating responses. It supports both typed transcripts and real meeting audio files processed through a WhisperX transcription pipeline. Responses are converted to speech using ElevenLabs TTS with an Egyptian Arabic voice.

---

# 📌 Project Components

### 📂 data
Contains meeting transcript datasets used for testing the models and the RAG system.
- `meeting_transcripts.json` — original dataset
- `meeting_transcripts_mixed.json` — Arabic/English mixed dataset
- `meeting_transcripts_mixed_rag.json` — dataset used for RAG pipeline
- `meeting_transcripts_audio.json` — dataset generated from real audio transcripts

### 📂 prompts
Prompt templates used for:
- Meeting summarization
- Task extraction
- Mixed-language transcript understanding

### 📂 llm_testing
Python scripts used to test different **LLM models**.
```
llm_test_llama.py
llm_test_mixtral.py
```

### 📂 llm_results
Contains outputs generated from the tested LLM models.

### 📂 RAG
Core modules implementing the **Retrieval-Augmented Generation pipeline**.
- **chunking.py** → splits meeting transcripts into smaller chunks
- **embeddings.py** → generates vector embeddings using `all-MiniLM-L6-v2`
- **vector_store.py** → stores embeddings in ChromaDB with cosine similarity
- **rag_pipeline.py** → retrieves relevant context and generates answers using Groq LLM

### 📂 audio_pipeline
Single pipeline script that handles the full audio processing flow.
- **audio_pipeline.py** → runs all 3 steps in order:
  1. Preprocesses audio (WAV, mono, 16kHz, silence removal)
  2. Transcribes using WhisperX with speaker diarization
  3. Builds RAG-ready JSON dataset from transcripts

### 📂 TTS
Text-to-Speech module using ElevenLabs and edge-tts as fallback.
- **coqui_tts.py** → detects language, converts tasks JSON to speech, calls ElevenLabs API

### 📂 audio_clean
Contains preprocessed audio files ready for transcription.

### 📂 transcripts
Contains transcribed meeting text files generated by WhisperX.
Each file includes speaker labels and timestamps.
```
[0.11-1.09] SPEAKER_00: Good morning, everyone.
[11.06-11.62] SPEAKER_01: Good morning.
```

# ⚙️ System Workflow

### Full Pipeline (Audio → RAG → TTS)
```
Meeting Audio Files (audio/)
        ↓
audio_pipeline.py
  ├── Audio Preprocessing (mono, 16kHz, silence removal)
  ├── WhisperX Transcription (speech-to-text + speaker diarization)
  └── JSON Dataset Builder (transcripts → meeting_transcripts_audio.json)
        ↓
Chunking → Embeddings → ChromaDB
        ↓
User Query
        ↓
Similarity Search (top-k relevant chunks)
        ↓
Groq LLM (llama-3.3-70b-versatile)
        ↓
Generated Answer
        ↓
ElevenLabs TTS (Egyptian Arabic voice)
        ↓
Audio Response (RAG/audio_results/)
```

# 🚀 Features
- **Meeting summarization** in the same language as the meeting
- **Task extraction** *(task, responsible person, deadline)*
- **Question answering** about meeting content
- Support for **Arabic (Egyptian dialect) and English** transcripts
- **Automatic language detection** — responds in Egyptian Arabic or English based on context
- **RAG-based semantic search** over meeting content
- **Audio-to-transcript pipeline** using WhisperX
- **Speaker diarization** (identifying who said what via SPEAKER_00, SPEAKER_01, etc.)
- **TTS with Egyptian Arabic voice** via ElevenLabs
- **Skip logic** — already processed files are never re-processed
- Results saved automatically to `RAG/rag_results/` for evaluation

# 🔑 API Keys & Setup

### Groq API Key
1. Go to [console.groq.com](https://console.groq.com)
2. Create an account and generate an API key
3. Add it to your `.env` file:
```env
GROQ_API_KEY=your_groq_api_key_here
```

### HuggingFace Token (for WhisperX diarization)
1. Go to [huggingface.co](https://huggingface.co) and create an account
2. Go to Settings → Access Tokens → New Token
3. Accept the terms for:
   - [pyannote/speaker-diarization-3.1](https://huggingface.co/pyannote/speaker-diarization-3.1)
   - [pyannote/segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0)
4. Add the token in `audio_pipeline/audio_pipeline.py`:
```python
HF_TOKEN = "your_hf_token_here"
```

### ElevenLabs API Key & Voice Setup

#### 1. Get your API Key
1. Go to [elevenlabs.io](https://elevenlabs.io) and create an account
2. Go to your Profile → API Keys
3. Copy your API key
4. Add it in `TTS/coqui_tts.py`:
```python
ELEVENLABS_API_KEY = "your_elevenlabs_api_key_here"
```

#### 2. Create an Egyptian Arabic Voice
1. Go to [ElevenLabs Voice Lab](https://elevenlabs.io/voice-lab)
2. Click **Create a Voice** → **Voice Design**
3. Paste this prompt:
```
Egyptian Arabic male voice, friendly, conversational, natural Egyptian dialect,
warm tone, clear pronunciation, slightly energetic, suitable for meetings,
speaks naturally like a native Egyptian, not formal Arabic,
mixes Egyptian colloquial with English technical terms naturally,
pronounces Arabic letters correctly, clear qaf (ق) pronunciation,
no Egyptian dialect letter substitution
```
4. Adjust settings:
   - **Loudness**: medium
   - **Guidance Scale**: medium-low (for more natural output)
5. Generate and preview the 3 voice options, pick the best one
6. Click **Select Voice** and give it a name
7. Go to **My Voices**, find your voice, and copy the **Voice ID**
8. Add it in `TTS/coqui_tts.py`:
```python
ELEVENLABS_AR_VOICE = "your_voice_id_here"
```

# ▶️ Running the Project

## Option A — Audio Pipeline (Audio → Transcripts → RAG)

> ⚠️ WhisperX requires Python 3.10. Use the `venv310` environment for this step.

### 1️⃣ Activate the Python 3.10 virtual environment
```bash
venv310\Scripts\activate
```

### 2️⃣ Add your audio files
Put your `.mp3`, `.wav`, or `.m4a` files in the `audio/` folder.

### 3️⃣ Run the full audio pipeline
```bash
python audio_pipeline/audio_pipeline.py
```

This will:
- Preprocess audio → `audio_clean/`
- Transcribe with WhisperX → `transcripts/`
- Build JSON dataset → `data/meeting_transcripts_audio.json`

> ✅ **Skip logic**: already processed files are automatically skipped — safe to re-run anytime you add new audio files.

### 4️⃣ Switch back to main environment
```bash
venv\Scripts\activate
```

---

## Option B — RAG Pipeline (Answer Questions about Meetings)

### 1️⃣ Activate the main virtual environment
```bash
venv\Scripts\activate
```

### 2️⃣ Install dependencies
```bash
pip install chromadb sentence-transformers groq python-dotenv edge-tts
```

### 3️⃣ Add your API key
Create a `.env` file in the project root:
```env
GROQ_API_KEY=your_groq_api_key_here
```

### 4️⃣ Run the assistant
```bash
python main.py
```

### 5️⃣ Choose a task when prompted
```
1 - Generate Meeting Summary
2 - Extract Tasks
3 - Ask a Question
4 - Exit
```

> ✅ The system auto-builds the ChromaDB on first run. No manual chunking/embedding steps needed.
